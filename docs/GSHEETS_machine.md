# `google_sheets_service` — карта модуля

Документ для последующих сессий. Описывает, **что сделано** в
`new_version/google_sheets_service`, какие инварианты нельзя нарушать и что
делать дальше. Парный документ по api — [API_machine.md](API_machine.md).

Пиши на русском: сообщения пользователю, комментарии, докстринги, сообщения
коммитов.

## 1. Что это

Единственная часть системы, которая ходит в Google. Своей базы нет — всё
состояние живёт в api и приезжает по HTTP. Работа устроена так:

1. `POST /sheet-sync-tasks/claim` отдаёт пачку созревших задач;
2. по каждому документу один раз сверяется скелет (документ, листы, доступы);
3. задачи выполняются по одной, с паузой между ними;
4. каждая закрывается через `complete` либо возвращается в очередь через `fail`.

Задача очереди говорит только «этот лист устарел», без подробностей о том, что
изменилось. Поэтому лист всегда строится **целиком из текущего состояния базы**:
повтор безопасен, порядок не важен, а потерянная задача чинится следующей же
правкой.

Проверено, а не заявлено:

| Проверка | Команда | Результат |
|---|---|---|
| Линтер | `uv run ruff check .` | чисто |
| Типы | `uv run mypy api google_sheets_service tests` | чисто, 272 файла |
| Тесты | `uv run pytest` | 336 тестов |
| Обратимость миграции | `upgrade head` → `downgrade base` → `upgrade head` | проходит |
| Миграция == `create_all` | `pg_dump` обеих схем + diff | идентичны |
| Сборка образа | `docker compose build google-sheets-service` | собирается, приложение поднимается |
| Сквозной прогон | `docker compose up` + настоящий Google | документ, четыре листа, импорт, операция, перевод, удаление, доступы, восстановление удалённой вкладки — без единой неудачной задачи |

## 2. Инварианты, которые нельзя нарушать

1. **Перерисовка — один `spreadsheets.batchUpdate`.** Он атомарен: Google
   применяет либо все запросы, либо ни одного. Разбить его на «очистить,
   записать, оформить» значит вернуть баг старой версии, где сбой между первым
   и вторым оставлял пользователя перед пустым листом.
2. **Хвост затирается до конца сетки.** Прошлого сервис не помнит — своей базы у
   него нет, — и единственная надёжная граница затирания — размер листа. Без
   этого удаление операции оставляло бы последнюю строку на месте.
3. **Деньги остаются `Decimal` до самой границы с Google.** Приведение к `float`
   живёт ровно в одном месте — `values.number_cell`. Складывать и группировать
   во `float` нельзя: копейки поплывут.
4. **`to_cell_text` нормализует прочитанное.** `UNFORMATTED_VALUE` возвращает
   числа, а api принимает строки. Наивный `str` превращает флаг `Active` в
   `"1.0"`, и `api/validation.py` отвергает лист целиком. `bool` проверяется
   **раньше** `int`: в Python он его подкласс.
5. **Сверка скелета предшествует любой задаче документа** и выполняется один
   раз за проход. Отсюда свойство, ради которого она и сделана: перерисовке
   никогда не нужно проверять, существует ли лист.
6. **Метка `appProperties` ставится сразу после создания документа.** Она делает
   создание идемпотентным. Убрать её — значит вернуть сирот: таблица создана,
   ответ api потерян, повтор заводит вторую.
7. **Документ создаётся сразу с листами справочников.** Без явного списка Google
   заводит собственный «Лист1» на 1000×26, и тот остаётся первой вкладкой
   навсегда: в `sheet_mappings` его нет, а удалять чужие листы сверка не должна.
   Проверено вживую — с пустым списком лист появлялся.
8. **Лист подхватывается по заголовку, если запись о нём потерялась.** Заголовки
   листов уникальны, и попытка создать второй `Categories` получила бы отказ
   Google — документ стало бы нечем починить. Оформление при этом идемпотентно:
   прежние защиты снимаются перед наложением новых, иначе каждая сверка
   добавляла бы документу ещё один слой.
9. **Период получает листы, если он открыт или по нему есть работа в этом
   проходе.** Движок передаёт в сверку периоды своих задач. Одних открытых мало:
   ролловер, закрывая месяц, напоследок его перерисовывает — пользователь мог
   добавить операцию в последние минуты. Удали он к тому времени вкладку, задача
   не нашла бы листа и падала бы вечно: терминальной такая ошибка не считается.
   Периоды, о которых никто не спрашивал, листов по-прежнему не получают —
   иначе документ, привязанный спустя годы, оброс бы пустыми вкладками за всю
   историю.
10. **Импорт сам перерисовывает лист.** Не дожидаясь отдельной задачи — иначе
    между записью в базу и перерисовкой остаётся окно с пустыми
    идентификаторами, и второй `/sync` в этом окне создаёт дубликаты категорий.
11. **Терминальность определяет код ответа Google, а не число попыток.** 400,
    401, 403, 404 — терминальные; 429 и 5xx — нет. Незнакомая ошибка
    терминальной не считается никогда.
12. **Ошибка одной задачи не роняет проход**, ошибка сверки проваливает все
    задачи своего документа и только их.
13. **Сброс пула соединений в начале каждого прохода.** httplib2 не проверяет
    живость сокета из пула; без сброса проход виснет до таймаута на первом же
    запросе к протухшему соединению.
14. **Один воркер.** Очередь выдержала бы несколько, но квота Google — 60
    запросов в минуту на **проект**, и разгонять её нечем.

## 3. Раскладка листов

Унаследована от старой версии дословно. Описания — в `sheets/layouts.py`.

| Лист | Заголовок | Колонки | Защита |
|---|---|---|---|
| `Categories` | фиксированный | ID · Active · Income · Cost · Name · Associations · Product types | шапка и `ID` |
| `Bills` | фиксированный | ID · Active · Name · Associations · Start balance · Current balance | шапка, `ID`, `Current balance` |
| Операции | `2026-08-01` | ID · Date · Amount · Name · Category · Type · Notes · Source · Check | лист целиком |
| Статистика | `Stat. 2026-08-01` | Category · Total · по колонке на день | лист целиком |

Правит пользователь только `Categories!B:G` и `Bills!B:E` — ровно то, что
читается обратно. Пустой список редакторов в защите означает «править может
только владелец файла», а владелец — сервисный аккаунт.

Статистика: строка «Общие доходы» и активные категории дохода, **одна пустая
строка**, «Общие расходы» и активные категории расхода. Разделитель заполняется
пустыми ячейками, а не оставляется коротким: строка без ячеек в `updateCells`
означает «не трогать».

Перевод печатается строкой реестра: `Category` = «Перевод», `Source` =
«Кошелёк → Карта», сумма положительная.

## 4. Что изменилось в api ради этого шага

Миграция `7f3c1d9a4b02_sheet_sync_task_lease`.

- **Срок аренды задачи.** `claim` отбирает и `claimed_at IS NULL`, и просроченные
  захваты (`SHEET_SYNC_LEASE_SECONDS`, 5 минут). Без срока воркер, умерший между
  `claim` и отчётом, замораживал лист навсегда — и молча, потому что уведомление
  шлёт `fail`, которого в этом сценарии не будет. Индекс
  `ix_sheet_sync_tasks_claimable` из-за этого стал полным по
  `(claimed_at, next_attempt_at)`: партиальный такую выборку не покрывает.
- **Терминальные ошибки.** `POST /sheet-sync-tasks/{id}/fail` принимает
  `terminal`. Пауза сразу длинная (`SHEET_SYNC_TERMINAL_RETRY_SECONDS`, час),
  уведомление уходит с первой попытки. Задача из очереди **не снимается**:
  доступ могут вернуть, и лист обязан догнать сам.
- **Отказ в выдаче доступа.** `POST /spreadsheets/{id}/accesses/{id}/failed`
  удаляет запись и уведомляет пользователя. Оставить её ждущей нельзя: неверный
  адрес попадал бы в каждую последующую сверку.

## 5. Грабли

1. **`bool` — подкласс `int`.** В `to_cell_text` порядок проверок обязателен.
2. **`repr` для нецелого `float`.** `str(Decimal(1000.5))` даёт семнадцать знаков
   двоичного хвоста, `repr(1000.5)` — кратчайшую запись, читаемую обратно в то
   же число.
3. **Заголовки листов кавычатся всегда.** `Stat. 2026-08-01` содержит и пробел,
   и точки. Старая версия подставляла их в диапазон без кавычек и работала лишь
   по снисходительности Google.
4. **`addProtectedRange` не идемпотентен.** Повтор заводит вторую защиту поверх
   первой, поэтому `header_requests` сначала снимает уже наложенные — их
   идентификаторы приезжают в `SheetProperties.protected_range_ids`.
5. **Заливка статистики сбрасывается перед покраской.** Число категорий
   меняется, и укоротившийся блок иначе оставит крашеный хвост.
6. **`spreadsheets.get` без маски `fields`** возвращает документ целиком, со
   значениями всех ячеек всех листов.
7. **Синхронный SDK бросает сетевые ошибки мимо `HttpError`.** `TimeoutError`,
   `ConnectionError`, `ssl.SSLError`, `HttpLib2Error` перечислены в
   `TRANSIENT_ERRORS` — без этой ветки они убивают весь проход.
8. **Граф объектов собирается в `lifespan`, а не на импорте.** Иначе любое
   обращение к модулю лезло бы в сеть, в том числе из тестов.
9. **Фейки в тестах не наследуют настоящие клиенты**, а повторяют их форму и
   ведут журнал вызовов: предмет проверки здесь — порядок действий, а
   возвращаемого значения у прохода нет.

## 6. Что делать дальше

### `telegram_bot/` — сделан

Aiogram-3 фронтенд, описан в [BOT_machine.md](BOT_machine.md).

Уведомления, которые рождает этот сервис, доходят до пользователя так: api
толкает их боту фоновым циклом (`POST /notify`), а бот дочитывает пропущенное
при обращении пользователя. `IMPORT_ERROR` с русским текстом разбора листа и
`SYNC_FAILED` иначе не узнать никак — они рождаются здесь, когда HTTP-запроса
пользователя уже нет.

### Разбор чеков

Не сделан и вынесен в отдельный шаг — см. [BOT_machine.md](BOT_machine.md) §10.
Этого сервиса он не касается.

### Не сделано осознанно

- **Архивация старых листов.** Сетка точного размера сняла причину: лист
  статистики занимает 33 колонки вместо 50, реестр — 9 вместо 26.
- **Несколько воркеров.** Квота Google общая на проект.
- **Отдельный лист переводов.** Перевод — обычная строка реестра.
