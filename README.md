# Cost accounting — новая версия

Учёт личных расходов. Postgres — источник истины, Google Spreadsheet — отчётная
поверхность и интерфейс редактирования справочников.

Система состоит из трёх частей:

| Часть | Состояние | Ответственность |
|---|---|---|
| `api/` | готов | Владеет Postgres. Вся предметная логика и все деньги |
| `google_sheets_service/` | готов | Единственный, кто ходит в Google API. Разгребает очередь перерисовки листов, читает правки пользователя и отдаёт их в api |
| `telegram_bot/` | **этот шаг** | aiogram-фронтенд: разбирает ввод, зовёт api, печатает ответ по-русски |

## Что сделано на этом шаге

Telegram-бот: текстовые команды с подбором категорий и счетов по псевдонимам,
мастер создания таблицы, операции и переводы, работа со справочниками через
Google-лист. Плюс доставка уведомлений о фоновой работе — api сам толкает их
боту, а бот дочитывает пропущенное при обращении пользователя.

Разбор чеков в этот шаг не входит и появится отдельно вместе с логикой
наполнения очереди.

Подробности: [docs/BOT_machine.md](docs/BOT_machine.md).

## Ключевые архитектурные решения

**Api никогда не ходит в Google.** Изменение данных — одна короткая транзакция в
Postgres, которая заодно пишет строку в очередь `sheet_sync_tasks`. Отдельный
сервис разгребает очередь и перерисовывает листы, повторяя при сбоях. Поэтому
операция не может завершиться сообщением об ошибке после того, как деньги уже
списаны, — сценарий двойного списания при таймауте на стороне Google исчезает.

**Задача в очереди описывает не изменение, а устаревание.** Строка означает
«лист X таблицы Y больше не соответствует БД». Уникальный ключ
`(spreadsheet_id, target, period_id)` схлопывает десять быстрых правок в одну
задачу, а перерисовка идёт из текущего состояния БД целиком — поэтому повтор
безопасен, а порядок обработки не важен.

**Баланс счёта — производная величина.** Колонки `current_balance` нет: баланс
считается агрегатом от начального баланса, операций и переводов. Расхождение
баланса с реестром становится невыразимым.

**Период — строка в таблице, а не подвижный указатель.** `periods` с уникальным
`(spreadsheet_id, start_date)` делает ролловер идемпотентным и позволяет догнать
любое число пропущенных месяцев. Границы полуинтервальные: `[start, end)`.

**Деньги — `NUMERIC(14,2)` и `Decimal`.** Ни одного `float`, ни одного
округления по пути от БД к листу.

**Принадлежность чужой таблице невыразима.** Составные внешние ключи
`(category_id, spreadsheet_id) → categories(id, spreadsheet_id)` не дают
сослаться на категорию из чужого документа — раньше это проверялось вручную в
каждом сервисе и местами было забыто.

## Запуск

```bash
cp env/api.env.example env/api.env
cp env/postgres.env.example env/postgres.env
cp env/google_sheets_service.env.example env/google_sheets_service.env
cp env/telegram_bot.env.example env/telegram_bot.env
# заполнить пароли, положить ключ сервисного аккаунта в secrets/google_sa.json,
# указать TELEGRAM_BOT_TOKEN и ALLOWED_TELEGRAM_IDS
docker compose up -d --build
curl -s localhost:8010/health          # api
curl -s localhost:8011/health          # отчёт последнего прохода по очереди
```

Миграции применяет `scripts/entrypoint.sh` при старте контейнера api.

`google_sheets_service` работает без входящих запросов, поэтому его `/health`
отдаёт не «жив ли процесс», а итог последнего прохода: сколько задач взято,
сделано и провалено. Ручной проход — `curl -X POST localhost:8011/sync`.

## Разработка

```bash
uv sync
uv run ruff check .
uv run mypy api google_sheets_service telegram_bot tests
```

Тестам нужен настоящий Postgres 16 (схема использует нативные enum,
`GENERATED ... AS IDENTITY` и `UNIQUE NULLS NOT DISTINCT`, поэтому SQLite не
подходит):

```bash
docker run -d --name pg-test -e POSTGRES_PASSWORD=test -p 5544:5432 postgres:16
uv run pytest
```
